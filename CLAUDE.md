## Approach
- Read existing files before writing. Don't re-read unless they have changed.
- Be thorough in reasoning and concise in output.
- Skip files larger than 100KB unless they are required.
- Do not guess APIs, versions, flags, commit SHAs, package names, or implementation details. Verify them by reading the code or official documentation before making assertions.
- Prefer modifying existing code over rewriting it unnecessarily.
- Make the smallest correct change that satisfies the request.

## Communication
- Keep responses as short as possible.
- Minimize token usage.
- Avoid unnecessary explanations.
- Only explain decisions when asked or when they are important for understanding.
- Only ask questions when absolutely necessary to continue.
- Prefer doing the work over describing what you are going to do.
- No sycophantic openers or closing fluff.
- No emojis or em-dashes.
- Answer me in english always.

## Code Style
- Do not write inline comments unless explicitly requested.
- Keep function, class, and module docstrings to one or two concise lines when genuinely necessary.
- Do not add documentation for obvious code.
- Prefer clear naming and readable code over comments.

## Documentation
- Do not create summary, report, changelog, notes, progress, or next-step files unless explicitly requested.
- Do not generate files such as SUMMARY.md, NEXT_STEPS.md, CHANGES.md, REPORT.md, NOTES.md, TODO.md, LOG.md, or similar.
